1. 개발 과제의 요약
본 과제는 시니어 및 만성질환자의 낮은 복약 순응도 문제를 해결하고, 보호자의 원격 관리 부담을 최
소화하기 위한 '시니어·만성질환 환자 맞춤형 복약관리 AI 에이전트 서비스(삐약이)' 개발을 목표로 한다.
기존 복약 관리 애플리케이션이 지닌 텍스트 위주의 복잡한 수동 입력 방식과 단순 알림으로 인한 알림
피로도의 한계를 극복하기 위해, 본 시스템은 다음과 같은 차별화된 지능형 기술을 단일 애플리케이션
내에 통합 구현한다.
◇ 동적 맞춤형 UI 및 클라우드 네이티브 보안 아키텍처: React Native와 Zustand 상태 관리를 활용하
여, 단일 앱 내에서 로그인된 사용자 역할(시니어/보호자)에 따라 최적화된 UI/UX 화면으로 동적 분기된
다. 백엔드는 안정성이 검증된 Java 21 기반의 Spring Boot 3.5.3과 MySQL 8.4.5를 채택하여 RESTful
API 서버를 구축하였다. 특히, 민감한 처방전 이미지는 서버를 거치지 않고 Presigned URL(5분 만료) 방
식을 통해 클라우드 스토리지(NCP Object Storage)로 직접 업로드하도록 설계하여 백엔드 병목을 방지
하고 보안성을 극대화했다.
◇ 시니어 주도적 복약 관리 (비동기 처방전 파싱 및 MCP 기반 DUR 검증): 처방전 촬영 시 Naver
Clova OCR을 통해 텍스트와 좌표(X, Y)를 추출하며, Y축 병합 알고리즘을 거친 데이터를 경량화 모델인
GPT-5.4-nano를 활용해 투약 정보로 정형화(JSON)한다. 무거운 연산으로 인한 앱 타임아웃을 방지하기
위해 HTTP 202 응답 기반의 비동기 큐잉(Job Queue) 처리를 적용하였다. 추출된 데이터는 MCP(Model
Context Protocol) 기반 자율형 에이전트가 건강보험심사평가원 DUR 공공 API를 자율적으로 호출하여
병용/연령 금기 사항을 사전에 경고한다.
◇ 시니어 능동적 참여 유도 (객체 인식 및 멀티모달 대화형 AI): 시니어의 복약 인증 시, Vision
LLM(GPT-5.4-mini) API를 통해 이미지 내 알약의 개수를 정확히 추출하고 DB에 저장된 1일 예상 복용
량과 대조하여 복약을 인증한다. 또한 whisper-1 (ko) 모델(STT) 및 TTS-1을 결합한 대화형 AI 에이전트
'삐약이' 캐릭터를 통해 음성 상호작용을 지원하며, 연속 복약(Streak) 달성 시 가상 재화(알) 보상을 제
공하는 게이미피케이션으로 자발적인 복약 습관 형성을 유도한다.
◇ 가족 안전망 구축 (다중 계층 스케줄링): Spring Boot 스케줄러와 Firebase Cloud Messaging (FCM)
을 결합하여, 시니어의 식사 시간에 맞춘 복약 알림을 발송한다. 미복용 상황이 30분을 초과할 경우 보
호자에게 즉각적인 이상 탐지 긴급 알림을 발송함으로써 독고사 방지 및 가족 간 연결성을 강화하는 신
뢰성 높은 디지털 헬스케어 플랫폼을 완성한다.

2. 단위 및 통합 테스트 주요 방어 시나리오
단순 기능 점검을 넘어, 실제 서비스 배포 시 발생할 수 있는 주요 시스템 예외 상황 및 법적 리스크
(컴플라이언스)에 대한 강력한 방어력을 평가한다.
◇ MCP 도구 자율 호출 및 인프라 장애 대응: 삐약이 통합 서버(AC003)가 통제하는 내부망 DUR 인프
라 호출 또는 외부 카카오 인증 서버(AC004) 접속 지연 시, 혹은 GPT-4o-mini의 MCP(Model Context
Protocol) 자율 호출 과정에서 타임아웃이 발생할 경우 전체 앱이 멈추지 않고 적절한 Fallback UI(안내
팝업 및 사용자 수동 전환 로직)를 제공하는지 평가한다.
◇ 네트워크 단절 및 FCM 토큰 만료 대응: 시니어의 기기가 오프라인 상태이거나 FCM 푸시 토큰이
만료되어 알림 발송이 실패할 경우, 백엔드 스케줄러가 마지막 접속 타임스탬프를 확인해 보호자에게 '
연결 끊김 경고'를 즉각 대체 발송하는지 평가한다.
◇ LLM 환각(Hallucination) 방어 및 DUR 명칭 불일치 대응: AI 모델이 추출한 약품명에 오타가 포함되
어 DUR DB와 불일치할 경우, 문자열 유사도를 통해 대체 약품 3개를 올바르게 추천하는지 평가한다.
더불어 AI 오판으로 인한 의료 사고를 방어하기 위해, 파싱된 데이터를 맹신하지 않고 사용자가 직접 원
본과 대조 후 '최종 승인' 버튼을 누르도록 유도하는 강제화 로직이 정상 작동하는지 점검한다.

3. 개념설계안
본 시스템은 모바일 클라이언트의 연산 부하를 최소화하고, 외부 인공지능 모듈과의 통신 안정성을 확
보하기 위해 백엔드 중심의 비동기 마이크로서비스 아키텍처를 채택하였다. 주요 개념 설계는 다음과

사용자 경험(UX)을 제공한다. 처방전 등록 시 백엔드의 비동기 파싱과 보호자의 '최종 승인'을 거쳐야만

하기 위해, 클라이언트가 서버로부터 5분 TTL의 Presigned URL을 발급받아 클라우드(NCP Object

시니어의 복약 결과에 따른 보상(게이미피케이션) 및 미복용 시의 보호자 연계까지 이어지는 전체 비즈
니스 흐름이다. 복약 시간 경과 시 시니어 기기의 알림을 강제 유지하고, 미복용 지속 시 보호자에게 긴

(TTS) 송출과 함께 연속 복약 카운트를 증가시켜 가상 재화(알) 보상을 지급함으로써 시니어의 능동적인

알약 수량 인식 도메인은 매년 수백 개의 신약(새로운 모양과 색상)이 출시되며, 시니어 사용자의 촬영
환경(조명 반사, 손떨림, 약봉지 텍스트 혼재 등)이 극도로 불규칙하다는 치명적인 변수가 존재한다.
실무에서 흔히 쓰이는 YOLOv11 모델은 추론 속도는 빠르나 수만 장의 Bounding Box 라벨링 구축 비
용이 발생하며, 학습되지 않은 새로운 모양의 약이 등장하면 인식률이 급락하는 데이터 드리프트 현상
에 매우 취약하다. Instance Segmentation(Mask R-CNN 등)은 알약이 겹쳐 있는 상황에서 객체를 잘 분
리하지만, 학습 비용이 천문학적이며 무거운 텐서 연산으로 인해 시니어의 저사양 스마트폰에서는 심각
한 발열과 배터리 소모를 유발한다.
반면, 멀티모달 비전 모델인 GPT-5.4-mini는 초거대 파운데이션 모델 기반의 제로샷 일반화 능력을 갖
추고 있다. 즉, 별도의 데이터 수집이나 재학습(Fine-tuning) 없이도 프롬프트 엔지니어링만으로 배경 노
이즈와 실제 알약을 논리적으로 구분하고 카운팅할 수 있는 압도적인 유연성을 발휘한다. 무엇보다 무
거운 딥러닝 추론 연산을 모바일 단말기가 아닌 외부 클라우드 AI 계층으로 100% 위임함으로써, 시니어
스마트폰의 환경적 제약을 무력화하는 최적의 클라우드 네이티브 아키텍처를 달성하였다.
